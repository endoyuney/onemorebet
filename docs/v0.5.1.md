# v0.5.1 — state integrity

The current prototype could lose a slot result on reload, pay an old result
into a different run, and restart its random sequence after loading.
These faults make progression and economy playtests unreliable.

## Changes

- Save the slot debit, pending result, and current RNG position together
  before animation. Restore and settle pending results once on load/import.
- Scope slot and coin animation callbacks to the run object that created them.
- Block bust, smash and new-run transitions while a slot bet is pending.
  Reset/import replace the run and invalidate old animation callbacks.
- Keep cosmetic slot animation off the seeded gameplay RNG stream.
- Preserve the Mulberry32 algorithm and store its advancing state, including
  seed zero. Import and load share migration and normalization.
- Migrate legacy unfinished slot bets by refunding their $50 debit and
  reversing the $7 contribution and spin counters. The original result and
  exact RNG position were absent from v5 saves and cannot be reconstructed.
- Skip unaffordable coins throughout the swarm, respect the hand budget,
  and rotate the cursor after the actual last selected coin.
- Remove completed scratch tickets when making an affordable new purchase;
  retain unfinished cards. Shop buttons and Space can continue at capacity.
- Preserve the smash result screen on boot/import, reject a locked slot
  action, and avoid replacing live progress with structurally invalid imports.

## Verification

16 automated tests pass. Running the same suite against the supplied v0.5
source produces 1 pass and 15 failures (some tests also require the new RNG
state API). Tests intentionally arrange edge-case states; they are not a
natural campaign playthrough or evidence of enjoyable pacing.

Real browser playtesting remains outstanding: the available browser's URL
policy blocked opening the local prototype. No visual or manual playtest
claim is made.

## Boundaries and follow-up

This is the first repair batch, not resolution of the entire previous audit.
Blue Six's non-monotonic luck return, prestige pacing, active-ability stacking,
the missing ending, automation handoff, and the three toys' gameplay roles
remain open. Financial parameters and unlock requirements were not retuned.
Save writes still use browser localStorage; a browser that refuses storage
cannot provide persistence, and malformed-save recovery needs further work.
Import validation is structural, not a complete adversarial save validator.

Before larger changes, test save/reload during a spin, import during a spin,
mixed expensive/cheap hands at low cash, and Space on a full completed-card
table in an actual desktop browser.
